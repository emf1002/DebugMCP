# DebugMCP 测试方法与回归记录

> 整理时间：2026-08-20。内容源自 8/18 调试功能开发期间的测试实战记录（CodeBuddy 会话记录）+ 工程现状核实。
> 配套文档：`docs/specs/2026-08-20-vsix打包与安装指南.md`。

## 1. 测试体系概述

DebugMCP 采用「**单元/集成测试（vscode-test）+ 运行时实测（debugmcp 工具链）**」双层验证：

1. **自动化测试**：`npm test`（`@vscode/test-cli`），覆盖 handler / routing / 矩阵回归 / 安全等。
2. **运行时实测**：打包安装后用 debugmcp 的 MCP 工具实际启停调试会话，验证 PID、端口、进程生命周期。

## 2. 测试命令与配置

```powershell
npm run check-types   # tsc --noEmit -p ./
npm run lint          # eslint src
npm test              # 自动先跑 pretest
```

- **pretest 自动链**：`npm run compile && npm run bundle && npm run lint`（编译 → esbuild 打包 → lint），全部通过才执行测试。
- **测试运行器**：`@vscode/test-cli`，配置 `.vscode-test.mjs`：

  ```js
  export default defineConfig({ files: 'out/test/**/*.test.js' });
  ```

- **VS Code 运行时**：`@vscode/test-cli` 默认会**下载一个独立的 VS Code stable 实例**到 `.vscode-test\`（首次或清缓存后）；本机已缓存 `vscode-win32-x64-archive-1.133.0`（完整 `Code.exe`），**之后直接复用缓存不再下载**。`extensions/`、`user-data/` 为测试隔离目录。
  - 若想彻底不下载：可在 `.vscode-test.mjs` 的 `defineConfig` 里配置 `version` 指向本机已安装的 VS Code/CodeBuddy 可执行文件路径（复用现有实例）。
- **断言**：Node `assert`。

## 4. 测试方法论

### 4.1 Mock 驱动（单元/集成）

- 用**接口 mock** 替代真实 VS Code Debug API，如 `IDebuggingExecutor` mock（`startDebugging`/`stopDebugging`/`getCurrentDebugState` 等全量实现）。
- 路由测试用 `RecordingHandler`（实现全部接口方法并记录调用），断言转发参数与返回。
- 矩阵测试用 `MockOpts` 参数化：`{ startResult, testDispatch, debugConfig, language, activeSession }` 组合各分支。

### 4.2 回归矩阵模式（`startDebuggingMatrix.test.ts`）

按「语言 × 启动路径 × 结果」构建矩阵，注释头标明验证点：
1. 启动成功 → 立即返回 "start command issued"（异步语义，不再阻塞等就绪/断点/超时）。
2. 启动失败（`startDebugging` 返回 false）→ 错误上抛。
3. 配置失败（`getDebugConfig` 抛错，如缺失构建产物）→ 错误上抛。
4. launch 路径（无 testName）与 test 路径（testName + Testing API）都覆盖。
5. 已有活跃会话时拒绝重复启动。

### 4.3 运行时实测（debugmcp 工具链）

自动化测试之外，按场景用 MCP 工具实测（记录于 8/18 会话）：

| 场景 | 验证方式 |
|---|---|
| 启动/停止 | `start_debugging` → `get_debug_state`（`sessionActive: true`）→ `stop_debugging` → `sessionActive: false` |
| 幂等 | 无会话停止幂等、重复停止幂等 |
| 进程终止 | 集成终端场景 stop 后检查 **JVM 终止 + 8080 端口释放**（stop 发送 Ctrl+C） |
| restart | 启动（PID 45828）→ `restart_debugging` 快速返回 → 旧进程终止、新进程启动（PID 16916、8080 无冲突）→ 停止无残留 |
| 状态残留 | `stop_debugging` 后 `activeDebugSession` 异步清空，立即 `get_debug_state` 可能仍 `true`，需稍候再查 |

## 6. 常见坑

| # | 坑 | 处理 |
|---|---|---|
| 1 | 缩进风格混用：`debuggingHandler.ts`/`debugMCPServer.ts`/`debugState.ts` 用 4 空格；`routingDebuggingHandler.ts`/`controlServer.ts`/`workspaceRegistry.ts` 用 **tab** | 改文件前先匹配目标文件缩进 |
| 2 | 新增 `IDebuggingHandler` 接口方法会破坏 `routing.test.ts` 的 `RecordingHandler`（实现类） | 同步补齐实现 |
| 3 | `IDebugConfigurationManager` mock 需补全所有新方法（如 `getAvailableDebugTargets: async () => []`） | 否则 TS 类型检查失败 |
| 4 | `DebugMCPServer` 构造新增可选参数 | 不影响测试（测试只用前 2 个参数） |
| 5 | `npm test` 需编译产物 | pretest 自动 compile+bundle；报 `out/` 缺失先跑 `npm run compile` |
| 6 | 临时日志文件（`test-output.log` 等）在工作区外 | 用 `Remove-Item` 删除（IDE 删除工具无法删工作区外文件） |

## 7. 质量门禁（提交前顺序）

1. `npm run check-types`（tsc 类型）
2. `npm run lint`（eslint）
3. `npm test`（回归全绿，LAN exposure 除外）
4. 打包 vsix 安装到 CodeBuddyDonghua（见打包安装指南）
5. debugmcp 运行时实测（启动/停止/restart/进程与端口）
