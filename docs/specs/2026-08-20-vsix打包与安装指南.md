# DebugMCP VSIX 打包与安装指南

> 整理时间：2026-08-20。内容源自 8/18 打包安装实战记录（CodeBuddy 会话记录）+ 工程现状核实（`package.json` v2.3.1、`debugmcpextension-2.3.0.vsix` 27.5MB）。

## 1. 打包

### 1.1 命令

```powershell
npx.cmd @vscode/vsce package
```

⚠ 必须用 **`npx.cmd`**：PowerShell 执行策略限制 `npx.ps1`，直接 `npx` 会报错。

### 1.2 自动构建链

`package.json` 的 scripts 触发链：

```json
"vscode:prepublish": "npm run package",
"package": "npm run check-types && node esbuild.js --production"
```

即 `vsce package` 会自动执行：**`tsc --noEmit`（check-types）+ esbuild 生产构建**（产物 `dist/extension.js`），校验通过后才产出 vsix。

### 1.3 产物

- 文件名：`debugmcpextension-<version>.vsix`（版本号取自 `package.json` 的 `version` 字段）
- 历史大小：2.3.0 ≈ 26.23 MB → 27.5 MB（随代码增长）
- 存放在工程根目录，被 `.gitignore`（`*.vsix`）忽略，**不入库**，需要时重新打包。

## 2. 安装目标环境

本机存在多个 CodeBuddy / VS Code 环境，扩展目录**彼此独立**：

| 环境 | 安装目录 | 扩展目录 |
|---|---|---|
| **CodeBuddyDonghua**（当前 IDE） | `C:\Users\zhouq\AppData\Local\Programs\CodeBuddyDonghua` | `~/.codebuddy/extensions` |
| CodeBuddy CN（国内版） | — | `~/.codebuddycn/extensions`（独立） |
| 标准 VS Code | — | `~/.vscode/extensions` |

> CodeBuddy 的扩展目录与 VS Code 同构（含 `extensions.json` 注册机制），但**互不相通**。

## 3. 安装命令与验证

### 3.1 安装（以 CodeBuddyDonghua 为例）

```powershell
& "C:\Users\zhouq\AppData\Local\Programs\CodeBuddyDonghua\bin\codebuddydonghua.cmd" --install-extension <vsix> --force
```

- CLI 路径：`<安装目录>\bin\codebuddydonghua.cmd`（须用 `&` 全路径或 `cmd /c` 调用；安装根目录下无 CLI）
- 扩展 ID：`ozzafar.debugmcpextension-enhanced`

### 3.2 验证

安装后检查产物是否包含新功能标识：

```powershell
Select-String -Path "~/.codebuddy/extensions/ozzafar.debugmcpextension-enhanced-<version>/dist/extension.js" -Pattern "<新工具名，如 get_debug_state>"
```

### 3.3 生效

安装完成后**重载 CodeBuddyDonghua 窗口**（`Ctrl+Shift+P → Reload Window`）。若 MCP 服务器仍运行旧代码，重载后生效。

## 4. 常见坑

| # | 坑 | 处理 |
|---|---|---|
| 1 | PowerShell 执行策略限制 `npx.ps1` | 用 `npx.cmd @vscode/vsce package` |
| 2 | `code --install-extension`（标准 VS Code CLI）只装到 `~/.vscode/extensions`，**不会**装进 CodeBuddy | 用对应版本的 CLI（如 `codebuddydonghua.cmd`） |
| 3 | 修改 `package.json` 的 `version` 后忘记重新打包 | vsix 文件名/扩展内部版本会与 README 徽标不一致；改版本号后必须重新打包 |
| 4 | 安装后 MCP 服务器仍运行旧代码 | 重载 CodeBuddyDonghua 窗口 |
| 5 | `vscode:prepublish` 失败 | 先本地 `npm run check-types` 修复类型错误 |
